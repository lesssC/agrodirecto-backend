# P1-03 — Pasarela de pago sandbox con webhook (SHOULD)

**Rama** `feat/P1-03-pasarela` · **PR** vie 27 · **Merge** sáb 28 · **Dueño** P1
**Go/no-go: jueves 26 por la noche.** Si no hay credenciales sandbox, no se implementa: el pago sigue simulado y rotulado (el contrato ya lo contempla).

## Objetivo
Que el estado `RETENIDO` solo lo confirme la pasarela vía webhook firmado, no el comprador.

## Contexto
`pagos/servicio/PagoService.java:38-49` (`retener()` simula; genera `SIM-xxxx`), `pedidos/web/PedidoController.java:54` (`POST /pedidos/{id}/pago`), migración V4 (pago/liquidación). Contrato en `contratos.md` sección Pago.

## Cambios
1. Interfaz `PasarelaPago { Cobro crearCobro(Pedido); void reembolsar(Pago); boolean verificarFirma(String payload, String firma); }`.
2. `PasarelaSimulada` (comportamiento actual, default y perfil `test`) y `PasarelaSandbox` (Mercado Pago o Culqi; elegir por credenciales disponibles). Selección con `pagos.proveedor` (`simulado|sandbox`).
3. `POST /api/pedidos/{id}/pago`: crea el cobro; en sandbox queda `PENDIENTE` y devuelve `urlCheckout`.
4. `POST /api/pagos/webhook`: valida firma HMAC (`X-Firma`, secreto `PAGOS_WEBHOOK_SECRET`), idempotente por `idExterno`, pasa pago a `RETENIDO` y pedido al estado pagado, y dispara las notificaciones existentes. Pedidos ya expirados no se reactivan.
5. Reembolso: al resolver disputa a favor del comprador y al cancelar un pedido pagado, llamar `reembolsar`.
6. Migración **V9**: `pago.id_externo` (único), `url_checkout`, `estado_pasarela`, `webhook_recibido_en`.

## Reglas de negocio
Se mantienen las existentes (comisión la paga el comprador; el agricultor recibe 100%; liberación automática y por confirmación). El pago al agricultor es manual en el MVP (ver P1-04).

## Criterios de aceptación
- Dado webhook con firma válida y pedido pendiente, entonces pago `RETENIDO` y notificación al productor.
- Dado firma inválida → 401 y sin cambios. Dado el mismo webhook dos veces → un solo cambio.
- Dado `proveedor=sandbox`, el comprador no puede pasar a `RETENIDO` llamando a `/pago`.
- Dado disputa resuelta a favor del comprador, se invoca `reembolsar` una vez.

## Tests
`PasarelaWebhookTest` con pasarela falsa (`@MockBean`/stub); tests existentes `PagoRetenidoTest` siguen verdes con `simulado`.

## Fuera de alcance
Pagos reales en producción, split de pagos, transferencias automáticas.

## Verificar
`./mvnw test`; manual con credenciales sandbox: crear pedido, pagar en la URL, ver que el webhook cambia el estado.
