# P1-01 — Endurecimiento de configuración (MUST)

**Rama** `fix/P1-01-config-prod` · **PR** mié 25 · **Merge** jue 26 · **Dueño** P1

## Objetivo
Que producción no pueda arrancar con secretos públicos del repositorio y que la superficie expuesta sea mínima, manteniendo las cuentas demo para la presentación.

## Contexto
- `src/main/resources/application.properties`: `JWT_SECRET` (l.27), `TOTP_CLAVE` (l.32), `DOBLE_FACTOR_DEMO` default `true` (l.35), `SMS_WEBHOOK_SECRET` default `cambiar-en-produccion` (l.37), orígenes con `https://*.workers.dev` (l.39), `SWAGGER` (l.47).
- `config/SeguridadConfig.java:115-123` (CORS), `render.yaml`, `usuarios/**/DobleFactorDemo.java:132-134` (secretos TOTP demo públicos).

## Cambios
1. Crear `application-prod.properties` y activar el perfil con `SPRING_PROFILES_ACTIVE=prod` en `render.yaml`.
2. En perfil `prod`, `JWT_SECRET`, `TOTP_CLAVE`, `SMS_WEBHOOK_SECRET` sin valor por defecto; clase `@ConfigurationProperties` + `@Validated` que exige longitud mínima (JWT ≥ 32 caracteres, TOTP_CLAVE el largo que ya espera `CifradoSecretos`). El arranque falla con mensaje claro si faltan.
3. `DOBLE_FACTOR_DEMO` default `false`. Cuando es `true`, los secretos TOTP demo se leen de variables (`DEMO_TOTP_ADMIN`, `DEMO_TOTP_AGENTE`) en vez de constantes del código; en dev local se mantienen valores por defecto.
4. CORS: `ORIGENES_PERMITIDOS` sin comodín por defecto en `prod` (dominio exacto del frontend). `render.yaml` conserva `sync: false`.
5. `SWAGGER=false` en `render.yaml` (decisión del equipo; si se quiere mostrar, protegerlo o activarlo solo durante la demo).
6. Quitar del README el secreto del webhook en el `curl` de ejemplo (usar `$SMS_WEBHOOK_SECRET`).

## Criterios de aceptación
- Dado perfil `prod` sin `JWT_SECRET`, cuando arranca, entonces falla con mensaje que nombra la variable.
- Dado origen no listado, cuando hace preflight a `/api/auth/login`, entonces CORS lo rechaza.
- Dado `DOBLE_FACTOR_DEMO=false`, no se crean cuentas con 2FA demo.
- Las cuentas demo siguen entrando con `demo1234` + código TOTP generado con el secreto de la variable.

## Tests
`ConfiguracionProdTest` (contexto falla sin secretos), `CorsTest` (origen permitido/no permitido). Los tests existentes siguen verdes (perfil `test`).

## Fuera de alcance
Rate limit (P1-02), rotación de secretos, perfiles adicionales.

## Verificar
`./mvnw test`; arrancar con Docker y `SPRING_PROFILES_ACTIVE=prod` sin variables → debe fallar; con variables → `/actuator/health` UP. Actualizar `docs/despliegue.md` (tabla de variables).
