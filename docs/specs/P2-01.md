# P2-01 — Subida de imágenes (MUST, desbloquea P3-04)

**Rama** `feat/P2-01-subida-imagenes` · **PR y merge** jue 26 · **Dueño** P2

## Objetivo
Que productores y compradores suban fotos (producto, evidencia de disputa y descargo) en vez de pegar URLs.

## Contexto
`catalogo/web/ProductoRequest.java:17,25` (comentario "la subida llegará con almacenamiento externo"; valida `(/|https://).*`), `confianza/web/DisputaRequest.java:12`, columna `evidencia_descargo_url` (V6). No existe endpoint multipart.

## Contrato
Ver `contratos.md` → Archivos.

## Cambios
1. Módulo nuevo `archivos/` con interfaz `AlmacenArchivos { String guardar(byte[], String tipo, String proposito); }`.
2. `AlmacenR2` (Cloudflare R2 vía API S3) o Cloudinary, según credenciales; `AlmacenLocal` (carpeta temporal) para tests y dev. Selección por `archivos.proveedor`.
3. `ArchivoController` `POST /api/archivos` (autenticado): detecta el tipo por contenido (no por extensión ni `Content-Type` del cliente), máximo 5 MB, nombre de objeto aleatorio (UUID), sin conservar el nombre original.
4. Configurar `spring.servlet.multipart.max-file-size=5MB`.
5. Ajustar validación de URLs en `ProductoRequest` y `DisputaRequest`/descargo para aceptar la URL del almacén (además de rutas `/images/...` ya usadas).
6. Variables en `render.yaml` y `docs/despliegue.md` (`sync: false`).

## Criterios de aceptación
- Dado un PNG válido de 1 MB y sesión → 201 con `url` accesible públicamente.
- Dado un `.exe` renombrado `.png` → 400 `ARCHIVO_TIPO_INVALIDO`.
- Dado 6 MB → 413. Sin token → 401.
- Un producto creado con esa `url` se guarda y se devuelve en `GET /api/productos/{id}`.

## Tests
`ArchivoControllerTest` (válido, tipo inválido, tamaño, sin sesión) con `AlmacenLocal`.

## Fuera de alcance
Redimensionar/optimizar, borrar archivos huérfanos, URLs firmadas privadas.

## Verificar
`./mvnw test`; curl multipart con token y abrir la URL devuelta.
