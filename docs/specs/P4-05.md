## Objetivo
Versión estable de ambos repos en producción, con smoke test y plan de contingencia.

## Contexto
`docs/despliegue.md` (guía actual), `render.yaml`, API `https://agrodirecto-api.onrender.com`, frontend `https://agrodirecto-avance-1.agrodirecto-fullstack.workers.dev`, MySQL Azure for Students B1ms (México Central). Render free duerme tras 15 min.

## Cambios / pasos
1. Cargar en Render las variables nuevas: secretos (P1-01), `ORIGENES_PERMITIDOS` exacto, `FRONTEND_URL`, `ARCHIVOS_*`, `CORREO_*`, `PAGOS_*`, `DEMO_TOTP_*`, `SPRING_PROFILES_ACTIVE=prod`.
2. Desplegar backend desde `main`; confirmar migraciones V9+ aplicadas y `/actuator/health` UP.
3. Frontend: definir `VITE_API_URL` **antes** de `pnpm build`; `wrangler deploy`.
4. Verificar CORS y WebSocket desde el dominio del frontend.
5. Keep-alive externo (cron-job.org o UptimeRobot, cada 10 min) a `/actuator/health`.
6. Azure: confirmar que la suscripción/crédito dura después del 2-dic; hacer `mysqldump` de respaldo; revisar reglas de firewall.
7. Smoke test en producción: registro, login, publicar con foto, comprar, pago, entrega, reseña, disputa, admin, recuperación de contraseña.
8. Actualizar `docs/despliegue.md` (variables nuevas) y `ROADMAP.md` (T10 → Completada; quitar "Avance 2").

## Criterios de aceptación
- Los 10 pasos del smoke test pasan en producción con cuentas demo.
- Una petición tras 20 min de inactividad responde (con keep-alive, sin cold start).
- Respaldo de BD guardado fuera de Azure.
