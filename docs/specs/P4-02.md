# P4-02 — CI en ambos repos (MUST)

**Rama** `chore/P4-02-ci` (en cada repo) · **PR** mié 25 · **Merge** jue 26 · **Dueño** P4

## Objetivo
Que cada PR corra pruebas automáticamente y no se mergee en rojo.

## Contexto
No hay `.github/` en el backend ni en el frontend. Backend: Java 21, Maven wrapper, tests con H2. Frontend: pnpm (ver `package.json` scripts `test`, `typecheck`, `lint`, `build`).

## Cambios
1. Backend `.github/workflows/ci.yml`: en `pull_request` y `push` a `main`: `actions/setup-java` (temurin 21, cache maven) → `./mvnw -B verify`.
2. Frontend `.github/workflows/ci.yml`: `pnpm/action-setup`, `setup-node` (versión de `package.json`/`.nvmrc`), `pnpm install --frozen-lockfile`, `pnpm typecheck`, `pnpm lint`, `pnpm test` (incluye `vinext build` según el script), `pnpm build`.
3. Documentar en `CONTRIBUTING.md` que se activa "Require status checks" en `main` (lo configura el dueño del repo en GitHub → Settings → Branches).

## Criterios de aceptación
- Un PR con test roto muestra check rojo; con todo bien, verde.
- El workflow termina en < 10 min.

## Fuera de alcance
Despliegue automático (CD), cobertura mínima obligatoria.

## Verificar
Abrir un PR de prueba en cada repo.
